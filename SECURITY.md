# Security Policy

## Supported versions

| Version | Security support |
| --- | --- |
| Latest stable [release](https://github.com/sensodent/BustaCode-Releases/releases/latest) | Supported for reports |
| Older releases | Upgrade and verify the issue persists |

## Report a vulnerability privately

**Do not create a public issue or discussion containing an exploit, private data, credentials or sensitive logs.**

1. Visit the repository [Security tab](https://github.com/sensodent/BustaCode-Releases/security) and use **Report a vulnerability** if GitHub private vulnerability reporting is enabled.
2. If it is not available, use a private contact method on the [repository owner's GitHub profile](https://github.com/sensodent), if provided. If no private channel exists, you may open a public issue asking the maintainer to establish one, **without sharing any vulnerability details**.

Helpful information: affected version, Windows version, impact and safe reproduction details. Share sensitive proof-of-concept material only in a confirmed private channel.

Examples in scope: update integrity, local tokens, agent permissions, MCP/SSH exposure, installer behavior and other BustaCode security boundaries. For vulnerabilities in third-party AI tools, extensions or services alone, use the respective vendor's security program.

Reports are prioritized by impact and reproducibility. No fixed response or remediation time is guaranteed.
